# 05 · OpenWrt / OpenClash 部署、验证和回滚

> 本仓库提供的是**规则片段**与**OpenClash 覆写模块**，不是完整订阅文件。保留已有节点、策略组、DNS、Fake-IP、转发设置及原有规则兜底。

## 部署前准备

1. 确认 OpenClash 使用 Mihomo（Meta/Smart）核心，并按已有底座配置工作；不要直接将这些片段当成完整配置启动。
2. 在 LuCI 界面查看**当前选中的真实配置文件名**，不要假定文件永远叫 `/etc/openclash/config/config.yaml`。
3. 通过 LuCI 下载该文件进行备份；或 SSH 后操作（按实际文件名修改）：

   ```sh
   CONFIG=/etc/openclash/config/当前正在使用的配置.yaml
   cp -p "$CONFIG" "$CONFIG.bak.$(date +%Y%m%d-%H%M%S)"
   ```

4. 确认实际配置拥有名为 `AI服务` 的策略组；如名称不同，需要同步调整规则引用。
5. **手动合并与覆写模块选其一**，不要重复注入两套规则。

## 方案 A：手动合并（首选）

1. RAM 较少先用 `config/rule-providers.yaml`，有充足内存可选择 `config/rule-providers-full.yaml`。
2. 只合并 `rule-providers` 中不存在或需要替换的键；**不要另建重复的顶层 `rule-providers:`**。
3. 只把两条 `rules` 插入现有 `MATCH` 及通用域名分流之前；不要覆盖已有 `rules`。
4. 保存后在 OpenClash 应用，检查日志是否存在配置解析、provider 下载或规则组不存在的错误。

## 方案 B：OpenClash 模块覆写

`config/overwrite-example.yaml` 是含 `[YAML]` 标记的**OpenClash 模块文件**，不是可以直接运行的 Mihomo YAML。通过 OpenClash 的覆写模块功能导入本地文件或你自己托管的 URL。**不要粘贴进** `/etc/openclash/custom/openclash_custom_overwrite.sh`，它是 Shell 文件。

该模块用 `+rule-providers` 合并 provider，用 `+rules` 前置插入规则。部分 OpenClash/iStoreOS 版本可能无法正确处理中文或 Emoji 策略组名；必须核对生成的运行配置。模块在其他版本上的适配需实机验证。

注意：不要将本模块和其他会强制替换整段 `rules` 的模块同时使用；若底座模块也修改规则，先检查模块应用顺序和最终运行配置。

## 校验

在开发电脑/CI 上安装 Python 3 + PyYAML 后：

```sh
python3 -m pip install pyyaml
python3 scripts/validate-config.py
bash -n scripts/check-upstream.sh
bash scripts/check-upstream.sh --light   # 可选：检查在线源，需 GitHub 网络连通
# bash scripts/check-upstream.sh --full # 全量黑名单较大，谨慎在小路由器运行
```

如果系统已有 `mihomo` 命令，可以在**完整合并后的配置**上运行 `mihomo -t -f /path/to/merged.yaml`（部分环境还需要设置 `-d`）；不能对本仓库规则片段或含 `[YAML]` 的模块文件直接执行该测试。

最后检查 OpenClash 运行日志、规则集/策略组、AI 站点是否走 `AI服务`、普通网站是否按原有国内外策略分流、局域网 DNS 是否正常。仅依据广告拦截测试站的「分数」无法证明没有误拦截。

## 回滚

出现断网、DNS 异常、路由器重启或策略组错误时：

1. 先关闭/移除新增的覆写模块，或恢复手动编辑前备份的原配置。
2. 重新应用原配置并确认基础网络连通，再逐条检查本方案注入的规则。
3. 若需要 SSH 恢复，先核对文件名，再执行 `cp -p /path/to/备份.yaml /etc/openclash/config/原文件名.yaml`。

不要删除原有订阅、DNS 或其他插件设置来“修复”一条规则引起的问题。
