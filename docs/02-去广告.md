# 02 · 去广告：白名单只排除拦截，不强制直连

## 默认版与完整版

- `config/rule-providers.yaml`（轻量）：`adguard_allow` + `oisd_small`，适合先在小内存设备验证。
- `config/rule-providers-full.yaml`（完整）：`adguard_allow` + `adguard_block`，规则更大；按内存和使用体验决定是否切换。
- **只能二选一**。条目数、体积与上游更新有关，不能将文档中的历史数字当作永久规格。

## 为何不用 `RULE-SET,adguard_allow,DIRECT`

广告白名单的意思是「不要因为广告黑名单而拦截」，不是「不经代理、强制直连」。
如果白名单命中的是原本需要走海外代理的域名，提前写 `DIRECT` 会覆盖原有分流策略。

现在默认规则采用 Mihomo 的逻辑表达式：

```yaml
rules:
  - 'AND,((RULE-SET,oisd_small),(NOT,((RULE-SET,adguard_allow)))),REJECT'
  - RULE-SET,ai-services,AI服务
```

完整版将 `oisd_small` 换成 `adguard_block`。这表示：**仅当命中黑名单、且没有命中白名单时才 REJECT**。
白名单域名会继续匹配后续 AI、GeoSite、国内外分流等规则，而不是自动直连。

## 部署注意

1. 将 `rule-providers` 中的各条目合并到当前使用的订阅配置，避免出现重复的 `rule-providers:` 顶级字段。
2. 将本方案两条规则插到原有通用规则（尤其 `MATCH`）之前；不要整段覆盖原有 `rules`。
3. 如果上游同名 provider 已存在，先对比 URL、行为、缓存路径，再决定是否替换。
4. 重新应用后，在 OpenClash 连接记录核实正常网站没有被意外强制直连；出现误杀时可以暂时删除本方案的 AND 拦截规则回退。
5. 不要额外叠加旧 DNS 广告过滤插件。参见 `05-部署验证与回滚.md`。
