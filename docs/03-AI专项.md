# 03 · AI 专项：精确分流优先

## 默认：经过人工筛选的内联规则

默认版与完整版都使用 `type: inline` + `behavior: classical` 的 `ai-services`，不依赖在线 AI 规则下载。主要覆盖 ChatGPT、Claude、Gemini、Grok、Perplexity、Copilot、Cursor 等常用 AI 入口及其明确的专用接口。

**不再把 `microsoft.com`、`bing.com`、`gstatic.com`、`live.com`、`stripe.com`、`notion.so` 等大型共享域名直接归入 AI 分组**。这可降低非 AI 网站错误选用 AI 出口的概率，但部分第三方身份验证、支付、验证码或更新接口可能仍按底座规则走其他分组；需要以 OpenClash 连接记录核对，针对具体问题补充精确域名。

```yaml
rule-providers:
  ai-services:
    type: inline
    behavior: classical
    payload:
      - DOMAIN-SUFFIX,chatgpt.com
      - DOMAIN-SUFFIX,claude.ai
      - DOMAIN-SUFFIX,gemini.google.com
rules:
  - RULE-SET,ai-services,AI服务
```

上面的代码仅展示几条关键域名，实际请使用 `config/rule-providers.yaml` 或完整版提供的完整内联清单。

内联清单**不会自动更新**；新增 AI 产品时需要维护配置并再次应用。请勿再沿用过去文档里「AI 规则每天自动更新」的说法。

## 按需启用上游广覆盖清单（可选）

如果确实需要上游的广覆盖自动更新，可以将默认 `ai-services` provider **整个替换**为：

```yaml
  ai-services:
    type: http
    behavior: classical
    format: yaml
    path: ./ruleset/ai-services.yaml
    url: https://raw.githubusercontent.com/rorojiao/clash_rules/master/rules/ai-services.yaml
    interval: 86400
```

这里 86400 秒是 Mihomo 的**检查间隔**，不代表上游一定每日发布新规则。上游列表包含大量非 AI 专用域名，启用前请自行复核、接受扩大分流范围的影响。不要同时定义两个同名 `ai-services` provider。

## 策略组及链式代理

- 使用本方案的前提是现有配置拥有**完全同名**的 `AI服务` 策略组；名称包含空格、Emoji 或不同汉字时都需要一致。
- 若没有这个组，请基于自己现有的策略组和节点创建，不要直接照搬虚构的节点名 `自动选择`。
- 如需前置中转，可参考 Mihomo 的 `dialer-proxy` 文档；它应在**节点**配置中引用确实存在的前置节点/策略组。
- 不要把代理订阅 URL、节点密码、API 密钥提交到公开仓库。
- 如果 OpenClash 的 YAML 模块在中文策略组名上发生编码问题，可以把实际策略组统一改名为 `AI`，并在配置片段、覆写模块的引用中同步替换，然后核验最终生成的运行配置。

## 排错

1. `AI服务` 无法启动：确认策略组存在、名称完全相同。
2. AI 站点没有进入该组：确认 AI 规则放在通用 `MATCH` 和宽泛 GeoSite 规则之前。
3. AI 网站登录、验证码或文件上传异常：查看连接记录并精确补充实际所需域名，而不是直接加入整个 `google.com`、`microsoft.com`。
4. AI 站点拒绝服务：出口 IP、地区、账户和服务政策也可能导致失败，不能仅用分流命中判断服务可用。
